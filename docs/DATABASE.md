# Database

PostgreSQL 14+ (17 in Docker). The schema is in [prisma/schema.prisma](../prisma/schema.prisma).
Migrations live in [prisma/migrations](../prisma/migrations):

| Migration | Contents |
|---|---|
| `…_init` | tables, enums, foreign keys, unique keys, indexes (generated by Prisma) |
| `…_integrity_constraints` | **hand-written**: `btree_gist`, exclusion constraints, CHECK constraints, append-only/immutability triggers |

```bash
npm run db:migrate        # apply (prisma migrate deploy) — safe for production
npm run db:migrate:dev    # create a new migration while developing
```

Prisma doesn't model exclusion/CHECK constraints or triggers, but it also ignores them when diffing,
which was verified: `prisma migrate diff` reports no drift. **Do not use `prisma db push`.** It would
create tables without these guarantees. The integration test `constraints.int-spec.ts` fails if any
constraint is missing.

## Entities

| Table | Purpose | Key columns |
|---|---|---|
| `User` | dashboard user | `email` (unique, lower-case), `passwordHash` (argon2id), `role`, `status` |
| `UserGroupScope` | which groups a CDS_ADMIN / LGI_VIEWER may access | PK `(userId, groupId)` |
| `RefreshToken` | rotating refresh tokens | `tokenHash` (sha256, unique), `familyId`, `replacedAt`, `revokedAt` |
| `CdsGroup` | CDS group | `nameNormalized` (unique, case-insensitive), `status` |
| `CdsSchedule` | weekly rule | `dayOfWeek` 1–7, `startLocalTime`/`endLocalTime` "HH:mm", `timezone`, `effectiveFrom`/`effectiveUntil` (dates), `status` |
| `AttendanceSession` | expected or ad-hoc meeting | `origin`, `occurrenceDate`, `plannedStart/End`, `status`, `openedAt`, `closedAt`, `heldConfirmation`, `cancellationReason`, … |
| `Member` | corps member identity | `fullName`, `stateCode` (unique, upper-case), `status`, `deactivatedAt` |
| `GroupMembership` | member ∈ group over `[joinedAt, leftAt)` | `endReason`, `transferredToMembershipId` |
| `Card` | physical NFC tag | `cardUid` (unique, upper hex), `status`, `revokeReason` |
| `CardAssignment` | member holds card over `[assignedAt, endedAt)` | `status`, `endReason`, `replacedByAssignmentId` |
| `Device` | attendance reader | `deviceIdentifier` (unique), `assignedGroupId`, `status`, `secretHash`, `credentialVersion`, `lastSeenAt`, `lastSyncAt`, `lastStatus` |
| `SyncEvent` | one row per device sync call | `type` (TOKEN/SNAPSHOT/UPLOAD/HEARTBEAT), `result`, item counts, `clockSkewMs`, `durationMs`, `errorCode` |
| `AttendanceEvent` | raw uploaded tap + immutable acknowledgement | `(deviceId, clientEventId)` unique, `payloadHash`, `capturedAt`, `receivedAt`, `ackStatus`, `ackReason`, resolved ids, `resolution` |
| `AttendanceRecord` | official attendance | `(sessionId, memberId)` unique, `membershipId`, `source` (DEVICE/MANUAL/REPROCESSED), `lateSync`, `status` (PRESENT/VOIDED) |
| `AuditLog` | append-only audit trail | `actorType`, `actorId`, `action`, `entityType`, `entityId`, `groupId`, `metadata`, `requestId`, `ip` |

All primary keys are UUIDv7 (time-ordered), except `AuditLog` (bigint identity). Instants are
`timestamptz(3)` in UTC. Calendar facts (`occurrenceDate`, schedule effectivity) are `date`.

### Entity relationships

```
CdsGroup 1─* CdsSchedule 1─* AttendanceSession *─1 CdsGroup
CdsGroup 1─* GroupMembership *─1 Member 1─* CardAssignment *─1 Card
CdsGroup 1─* Device 1─* AttendanceEvent ─0..1→ AttendanceRecord
AttendanceSession 1─* AttendanceRecord *─1 Member ; AttendanceRecord *─1 GroupMembership ; *─0..1 CardAssignment ; *─0..1 Device
Device 1─* SyncEvent 1─* AttendanceEvent
User 1─* UserGroupScope *─1 CdsGroup ; User 1─* RefreshToken
```

## Integrity guarantees enforced by PostgreSQL

| Guarantee | Constraint |
|---|---|
| Sync idempotency | `AttendanceEvent UNIQUE(deviceId, clientEventId)` |
| One official record per member per session | `AttendanceRecord UNIQUE(sessionId, memberId)` |
| An event produces at most one record | `AttendanceRecord UNIQUE(sourceEventId)` |
| Idempotent session generation | `AttendanceSession UNIQUE(scheduleId, occurrenceDate)` |
| A member is in one group at a time | `EXCLUDE gist (memberId =, tstzrange(joinedAt, leftAt, '[)') &&)` |
| One holder per card at a time | `EXCLUDE gist (cardId =, tstzrange(assignedAt, endedAt, '[)') &&)` |
| One card per member at a time | `EXCLUDE gist (memberId =, tstzrange(assignedAt, endedAt, '[)') &&)` |
| Meetings of a group never overlap (cancelled excluded) | `EXCLUDE gist (groupId =, tstzrange(plannedStart, plannedEnd) &&) WHERE status <> 'CANCELLED'` |
| No overlapping active schedules on the same weekday | `EXCLUDE gist (groupId =, dayOfWeek =, daterange(effectiveFrom, effectiveUntil, '[]') &&) WHERE status = 'ACTIVE'` |
| Ranges are valid | `leftAt > joinedAt`, `endedAt > assignedAt`, `plannedEnd > plannedStart`, `closedAt > openedAt`, `endLocalTime > startLocalTime` |
| State consistency | `CANCELLED ⇔ cancellationReason+cancelledAt`; `OPEN ⇒ openedAt+heldConfirmation`; `CLOSED ⇒ openedAt+closedAt+heldConfirmation`; `ACTIVE assignment ⇔ endedAt IS NULL`; `REVOKED card ⇔ revokedAt`; `REJECTED event ⇔ ackReason`; `VOIDED record ⇔ voidedAt+voidReason`; device records have `deviceId`+`sourceEventId` |
| Card UID format | `^[0-9A-F]{8,32}$` |
| Attendance never disappears | triggers block `DELETE` on `AttendanceRecord` and `AttendanceEvent` |
| Device acknowledgements are immutable | trigger blocks changes to `ackStatus`, `ackReason`, `clientEventId`, `payloadHash`, `capturedAt`, `cardUid`, … |
| Audit log is append-only | trigger blocks `UPDATE`/`DELETE` on `AuditLog` |

Unique and exclusion violations that escape service-level checks are mapped to HTTP 409 by the
global exception filter. Services translate the expected ones into specific codes
(`MEMBERSHIP_OVERLAP`, `CARD_ALREADY_ASSIGNED`, `SESSION_OVERLAP`, …).

## Indexes

| Access path | Index |
|---|---|
| Card lookup by UID | `Card(cardUid)` unique |
| Assignment valid at time T | `CardAssignment(cardId, assignedAt)` + GiST from the exclusion constraint |
| Member lookup / search | `Member(stateCode)` unique (name search is `ILIKE`) |
| Eligibility (member, group, time) | `GroupMembership(memberId, joinedAt)`, `(groupId, joinedAt)`, GiST |
| Session resolution by time | `AttendanceSession(groupId, plannedStart)` + GiST |
| Date-range reporting | `AttendanceSession(groupId, occurrenceDate)` |
| Session attendance | `AttendanceRecord(sessionId, status)` (+ unique `(sessionId, memberId)`) |
| Member history | `AttendanceRecord(memberId, capturedAt DESC)` |
| Device sync history | `SyncEvent(deviceId, createdAt DESC)`, `AttendanceEvent(deviceId, receivedAt DESC)` |
| Rejected-event review | `AttendanceEvent(ackStatus, resolution, sessionId)` |
| Maintenance job | `AttendanceSession(status, plannedEnd)` |
| Audit queries | `AuditLog(entityType, entityId)`, `(actorId, createdAt)`, `(groupId, createdAt)`, `(action, createdAt)`, `(createdAt)` |

## Transactions

- Each state change and its audit row commit together.
- Device ingestion uses one short transaction **per tap**: event insert, admission, record insert. A batch is never all-or-nothing.
- Lifecycle transitions use optimistic conditional updates (`UPDATE … WHERE id = ? AND status = ?`), so concurrent conflicting actions fail with 409 instead of overwriting each other.
- The maintenance job runs inside one transaction holding `pg_try_advisory_xact_lock`.

## Resetting a development database

`npm run db:reset` (`prisma migrate reset`) drops all data. Prisma asks for explicit confirmation.
The test database runs in memory (`tmpfs`) and is migrated automatically by the test runner.
